# DiskMigrator × Claude 연계 계획 (v2)

> **이 문서는 `mcp` 브랜치의 계획서입니다.**
> `master`(v1.4.1)는 손대지 않습니다 — 지금까지의 수동 버전은 그대로 쓸 수 있어야 합니다.

## 무엇을 만들려는가

사용자가 하고 싶은 말을 그대로 하면(*"새 SSD를 샀는데 지금 윈도우를 그대로 옮기고 싶어"*),
Claude가 **디스크 상태를 직접 읽어 정확히 진단하고**, **안전한 계획을 세워 설명하고**,
**사용자 확인 아래 실행하고**, **부팅까지 확인·복구**하는 흐름을 만듭니다.

제품 철학인 *"디스크만 고르면 되는 자동 판단"* 을 대화로 확장하는 것이며,
없던 기능을 만드는 게 아니라 **이미 검증된 엔진을 Claude가 쓸 수 있게 여는 일**입니다.

### 이 계획의 출발점 — 2026-08-04 부팅 조사

며칠에 걸친 조사에서 진단 스크립트를 열 개 넘게 그때그때 만들었습니다:
디스크·파티션 열거, 하이브 읽기(부팅 드라이버 89개 전수·빠른 시작·PnP 항목),
ESP 감사(파일·BCD·서명), 부팅 흔적 분석(파일 타임스탬프로 어디까지 갔는지),
전후 스냅샷 비교. **전부 읽기 전용**이었고, 도구로 있었다면 작업이 훨씬 짧았을 것입니다.
1단계는 그 경험을 그대로 옮기는 일입니다.

## 안전 원칙 — 먼저 못 박는다

> **Claude는 계획하고 설명한다. 지우는 버튼은 사람이 누른다.**

1. **읽기와 쓰기를 계층에서 분리한다.** 진단 도구는 물리적으로 쓰기 경로를 갖지 않는다.
2. **`SafetyGuard`를 우회할 수 없다.** MCP 계층은 엔진을 호출할 뿐, 안전 판정을 재구현하거나 무력화하지 않는다.
3. **파괴적 작업의 최종 확인은 앱 화면에서 사람이 한다.** Claude의 호출은 확인 카드를 띄우는 데까지다.
   모델명 확인 절차(현재 CLI·GUI와 동일)를 그대로 통과해야 한다.
4. **되돌릴 수 없는 것은 미리 말한다.** 계획 단계에서 "무엇이 지워지는지"를 Claude가 먼저 설명한다.
5. **로컬 전용.** 네트워크에 열지 않는다. 디스크 정보(시리얼·볼륨 레이블)는 민감 정보로 다룬다.

## 아키텍처 — 앱이 MCP 서버를 품는다

```
┌─ DiskMigrator.App (관리자 권한, 사용자가 평소처럼 실행) ─┐
│                                                          │
│   WPF UI  ←→  MainViewModel  ←→  엔진(Core/Windows)      │
│                     ↑                                    │
│                     │ 같은 프로세스, 같은 권한            │
│                     ↓                                    │
│   McpEndpoint (로컬 전용 + 토큰)                         │
└──────────────────────────┬───────────────────────────────┘
                           │
                    Claude Code / Desktop
```

**왜 이 방식인가**

- **UAC 팝업이 없다.** 앱이 이미 관리자 권한이므로 모든 진단이 바로 된다.
  (독립 서버 + 작업별 상승 방식은 대화가 UAC로 계속 끊긴다 — 2026-08-04 조사에서 실제로 겪음)
- **앱 화면과 상태를 공유한다.** Claude가 "지금 화면에서 디스크 2가 선택돼 있습니다"라고 말할 수 있고,
  확인 카드를 띄우고, 진행률을 함께 볼 수 있다.
- **앱이 꺼져 있으면 연결이 안 된다** — 당연하고, 오히려 안전하다.

**해결해야 할 것**

- 전송 방식: stdio는 프로세스 수명이 Claude에 묶여 부적합 → **로컬 HTTP(ASP.NET Core, 127.0.0.1 바인딩)**
- 인증: 앱 실행 시 토큰 생성 → 사용자가 복사해 MCP 설정에 넣거나, 앱이 설정 파일을 써 줌
- 포트 충돌 대비, 앱 종료 시 정리
- 패키지: `ModelContextProtocol.AspNetCore` (공식 C# SDK v2.0, .NET 8 지원)

## 3단계 로드맵

### 1단계 — 진단 (읽기 전용) · 위험 0

오늘 손으로 만든 것들을 도구로 만든다. **여기까지만 해도 즉시 가치가 난다.**

| 도구 | 하는 일 | 근거가 되는 기존 코드 |
|---|---|---|
| `list_disks` | 디스크·파티션·볼륨 열거(시스템/부팅/페이지파일 표시) | `WindowsDiskService` |
| `inspect_disk` | 한 디스크의 파티션 배치·파일시스템·사용량 | `DiskLayoutMap`, `NtfsUsageProbe` |
| `check_boot_readiness` | 부팅 준비 검사(BCD·저장소 드라이버·재개 이미지·서드파티 드라이버) | `BootReadinessCheck`, `ThirdPartyBootDriverScan` |
| `read_boot_drivers` | Start=0 드라이버 전수 + 파일 존재 확인 | `RegistryHive` |
| `read_fast_startup` | 빠른 시작·최대 절전 설정, `hiberfil.sys` 유무 | `UniversalRestore` 진단부 |
| `audit_esp` | ESP 파일 목록·BCD 덤프·부팅 관리자 서명 | 신규(오늘 스크립트 기반) |
| `inspect_image` | .vhdx 무결성(구조·파티션·chkdsk) | `ImageInspector` |
| `analyze_boot_trace` | 부팅 흔적 분석 — 커널이 어디까지 갔는지 | 신규(오늘 forensic 기반) |
| `snapshot_state` / `diff_state` | 전후 비교(서비스·BCD·ESP·드라이버) | 신규(오늘 snapshot 기반) |

### 2단계 — 계획·조언 · 여전히 쓰기 없음

| 도구 | 하는 일 |
|---|---|
| `evaluate_safety` | 원본→대상 조합의 안전성 판정(차단·경고 사유 전부) — `SafetyGuard` 그대로 |
| `plan_clone` | 무엇을 어디로 복사할지, 축소·확대가 필요한지, 예상 시간 — `ClonePlan`·`ResizePlanner` |
| `explain_boot_failure` | 진단 결과를 엮어 "왜 안 뜨는지" 설명 + 다음 조치 제안 |

여기서 Claude는 **근거를 들어 설명**한다: *"대상이 500GB인데 원본 사용량이 320GB라 축소로 가능합니다.
다만 D 파티션의 마지막 클러스터가 끝에 몰려 있어 조각 모음이 먼저 필요합니다."*

### 3단계 — 실행 (확인 게이트) · 신중하게

| 도구 | 하는 일 | 게이트 |
|---|---|---|
| `propose_clone` | 앱 화면에 확인 카드를 띄운다 | **사용자가 모델명 확인 후 실행** |
| `propose_backup` | 백업 대상·경로를 앱에 채운다 | 사용자가 시작 버튼 |
| `propose_restore` | 복원 계획을 앱에 채운다 | 사용자가 시작 버튼 |
| `get_progress` | 진행률·현재 구간·ETA 조회(읽기) | 없음 |
| `propose_boot_repair` | 부팅 복구를 제안 | 사용자 확인 |

**Claude는 실행 버튼을 누를 수 없다.** 제안까지가 전부다.

## 버전·브랜치 전략

| | `master` | `mcp` |

| 버전 | **v1.4.x — 수동 버전(안정)** | v2.x — Claude 연계 |

둘을 동시에 두고 싶다면 설치 경로·앱 이름을 분리해야 한다(`DiskMigrator 2`).

## 진행 순서

1. `mcp` 브랜치에 MCP 서버 뼈대 (`ModelContextProtocol.AspNetCore`, 로컬 바인딩, 토큰)
2. **1단계 진단 도구부터** — 하나씩 만들고 실제 디스크로 검증
3. 검증되면 2단계 계획·조언
4. 3단계 실행은 확인 게이트 설계를 먼저 합의한 뒤

각 단계는 **실기 검증을 거쳐야** 다음으로 넘어간다. 이 프로젝트의 기존 방식대로.

## 열린 질문 (착수 전 정할 것)

- 토큰을 어떻게 건넬 것인가 — 앱이 MCP 설정 파일을 직접 써 주는 게 편하지만, 그건 사용자 설정을 건드리는 일이다
- 앱이 안 떠 있을 때 Claude에게 무엇을 보여줄 것인가 — "앱을 실행해 주세요" 안내
- 진단 결과에 시리얼·볼륨 레이블이 들어간다. 대화 로그에 남는 것을 사용자가 알아야 한다
- WinPE 환경에서도 쓸 것인가(부팅 불가 PC 구조가 가장 필요한 상황인데, 거기선 Claude가 없다)
