복구

복구 파티션은 크기 그대로 오른쪽 끝으로 이동합니다. 파티션의 고유 GUID를 보존하므로 부팅 구성도 그대로 유효합니다.

그래서 둘 다 필요합니다. ②는 간단하지만 맨 뒤만 늘릴 수 있고(대신 MBR 디스크도 됩니다), ③은 아무 파티션이나 늘릴 수 있지만 파티션을 옮겨야 해서 GPT 전용입니다. 문제는 지금 화면이 이 둘을 독립된 체크박스로 보여준다는 것입니다 — 같은 질문(“빈 공간을 누구에게?”)의 답을 고르는 건데 둘 다 켤 수 있고, 그러면 하나가 조용히 무시됩니다. 그래서 라디오 3택으로 묶었습니다.

왜 이게 더 나은가. 지금은 “파티션 고르기 → GB 입력”이라 결과를 머릿속으로 계산해야 합니다. 막대에서 끌면 넓힌 크기와 남는 공간이 같은 화면에서 동시에 움직이므로 계산할 게 없습니다. 원본보다 작게는 끌리지 않아(확대 전용) 잘못된 값을 넣을 수도 없습니다 — 지금 입력란이 겪던 “숫자를 잘못 넣으면?” 문제가 아예 사라집니다.
막대 두 개가 서로 다른 것을 말합니다 — 반드시 갈라놔야 합니다. 위쪽 대상 막대는 “지금 이 내용이 지워집니다”(현재 상태, 안전 정보)이고, 조정용 막대는 “복제가 끝나면 이렇게 됩니다”(예상 결과, 계획 도구)입니다. 이걸 안 갈라놓으면 꽉 찬 대상 막대 바로 밑에서 “남는 공간 2.73 TB를 어떻게 할까요”라고 묻는 모순된 화면이 됩니다 — 지금 그 디스크의 남는 공간은 0이고, 2.73 TB는 복제 후에야 생기니까요. 그래서 두 막대를 완전히 같은 모양으로 위아래에 세우고, “변경 전 / 변경 후” 라벨 글자로만 시점을 갈랐습니다. 높이·테두리·사용량 띠·범례 형식이 같아야 두 그림이 같은 종류의 것으로 읽히고, 그래야 나란히 비교됩니다. 한쪽만 상자에 넣거나 색을 입히면 다시 다른 의미의 그래프로 보입니다 — 그래서 배경 상자도 두지 않았습니다. 결정은 대상 디스크를 보고 있는 자리에서 이뤄지는 것이 맞습니다 — 옵션 영역까지 내려가면 무엇에 대한 선택인지 다시 떠올려야 합니다.

다섯 색은 채도를 낮춘 뒤에도 색상(hue)이 서로 벌어지도록 잡았습니다 — 황토 · 회색 · 청색 · 청록 · 밝은 회색. 막대에서 조각을 구분하는 것이 이 색의 유일한 일이라, 예쁨보다 구별이 우선입니다.

위험색만은 손대지 않습니다. 디스크를 통째로 지우는 도구라 “대상 삭제”와 “차단”은 망설임 없이 빨강이어야 합니다. DC2626 그대로 둡니다. 오히려 주변이 차분해질수록 이 빨강만 더 또렷하게 튀어나옵니다 — 온화한 팔레트가 경고를 약하게 만드는 게 아니라, 경고를 유일한 강한 색으로 남겨 더 세게 만듭니다.

이렇게 하면 심각도가 색으로 자연스럽게 층을 이룹니다 — 차단 · 삭제(빨강) › 확인 필요(머스터드) › 참고(회색).

같은 이유로 디스크 배지도 갈랐습니다. 시스템 은 실행 중인 Windows 디스크라 실수로 지우면 치명적이므로 빨강, 착탈식 은 단순한 사실 표시라 선명한 파랑(2563EB)으로 구분합니다. 배지는 작아서 채도가 낮으면 눈에 들어오지 않으므로, 강조색(데님)보다 진한 파랑을 따로 씁니다.

타이포만 “중간”인 이유: 47곳을 한 번에 건드리므로 누락이 생기면 화면 곳곳에서 크기가 어긋납니다. 그래서 단계를 나눠 커밋합니다.

“남는 공간 옵션”은 화면만의 문제가 아닙니다. 지금 두 옵션은 같은 목적(남는 공간 활용)의 서로 다른 방법인데 별개 체크박스로 놓여 있습니다. 그래서 둘 다 켜면 리사이즈가 이기고 다른 하나는 조용히 버려집니다(CloneOrchestrator의 확장 분기). 게다가 마지막 파티션 확장은 대상이 원본과 같은 크기여도 켤 수 있어, 남는 공간이 없으면 아무 일도 일어나지 않습니다. 라디오 3택으로 묶으면 두 문제가 구조적으로 사라집니다 — 배타 선택이니 무시될 조합 자체가 없고, 남는 공간이 없으면 묶음 전체를 숨기면 됩니다. 위험도가 “중간”인 이유는 화면뿐 아니라 CloneOptions·ViewModel 배선까지 바뀌기 때문입니다.

진행 순서

단계마다 커밋을 나누고, 화면 캡처로 눈으로 확인한 뒤 다음으로 넘어갑니다.

A

색과 타이포그래피

레이아웃은 그대로 두고 색·글자 체계만 정리합니다. 배치가 안 바뀌어 실기 테스트에 영향이 적습니다.

  • App.xaml의 브러시를 온화한 값으로 교체 — Danger는 건드리지 않음. 한 파일에서 끝납니다
  • DiskLayoutViewModel의 파티션 색 5개 교체
  • App.xaml에 6단계 텍스트 스타일 정의
  • MainWindow.xaml의 인라인 FontSize 47곳을 스타일 참조로 교체
  • 폰트 스택을 리소스 한 곳으로 통일(현재 4곳 중복)
  • 175% 배율에서 한글 렌더링 모드를 눈으로 비교 후 결정
B

구성 재배치

체감이 가장 큰 단계입니다. 위 목업의 “제안”이 이 결과물입니다.

  • 디스크 목록에 세로 공간 우선 배분
  • 배치 막대에 원본 / 대상 머리글 추가 — 막대만 봐도 어느 디스크인지 알 수 있게
  • 옵션을 원본 막대 아래로 옮기고 안전 / 동작 2열로 재구성 — “변경 후”와 같은 그리드 행에 두어 윗선 정렬
  • 남는 공간 옵션을 대상 막대 아래로 — 체크박스 2개(마지막 파티션 확장 · 리사이즈)를 라디오 3택으로 묶어 옵션 영역에서 대상 막대 바로 밑으로 이동. 조용히 무시되는 조합 제거 + 남는 공간이 없으면 묶음 숨김
  • 확인 입력 + 실행 버튼 통합, 비활성 사유 노출
  • 1 · 2 · 3 단계 표식 — 실제로 순서가 있는 절차라서 번호를 씁니다
C

마감

선택 사항. 앞 두 단계가 끝난 뒤 남는 거슬림만 정리합니다.

  • 범례 줄바꿈 안정화
  • 모서리 반경 · 테두리 색 통일
  • 배지 대비 조정
지금은 착수하지 않습니다. 실기 테스트 중에 코드를 바꾸면 테스트 중인 exe와 달라져 원인 추적이 어려워집니다. 테스트 결과를 받은 뒤 A단계부터 시작하는 것을 권합니다. 화면 변화가 작은 A단계만 먼저 해두는 것도 가능합니다.
