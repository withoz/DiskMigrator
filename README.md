# DiskMigrator

Windows용 디스크 전체 클론 도구. 실행 중인 시스템 디스크를 포함해 디스크를 섹터 단위로 복제하고, 클론이 **다른 하드웨어에서도 부팅**되도록 마이그레이션합니다.

.NET 8 · WPF · MIT 라이선스

---

## ⚠️ 경고 — 먼저 읽으십시오

**이 프로그램은 대상 디스크의 모든 데이터를 영구히 삭제합니다. 실수하면 되돌릴 수 없습니다.**

- 사용 전에 **반드시 중요한 데이터를 백업**하십시오.
- 대상 디스크를 고를 때 모델명과 용량을 **두 번 확인**하십시오.
- **아무런 보증 없이 "있는 그대로"** 제공됩니다. 데이터 손실에 대해 제작자는 책임지지 않습니다 ([LICENSE](LICENSE)).

**대상이 원본보다 작아도, 원본의 파티션이 모두 들어가면 클론할 수 있습니다.** 판정 기준은 디스크 전체 크기가 아니라 **파티션이 실제로 차지한 끝**입니다 — 1TB 디스크에 파티션이 앞쪽 200GB만 있다면 500GB 대상에 그대로 복제됩니다. 파티션은 **위치를 하나도 바꾸지 않고** 복사하고, GPT 백업 헤더만 줄어든 대상의 끝에 다시 씁니다. 버려지는 것은 마지막 파티션 뒤의 빈 공간뿐이며, **원본에는 아무것도 쓰지 않습니다**(GPT 원본 전용).

파티션 **자체**가 대상보다 큰 경우는 파일시스템을 줄여야 하므로 여전히 차단됩니다. 이때는 원본에서 먼저 볼륨을 축소한 뒤 클론하십시오(자동 NTFS 축소는 계획 단계).

## 안전장치

디스크를 통째로 날릴 수 있는 도구이므로, 안전 검사가 이 프로젝트의 중심입니다.

**절대 차단** — 대상이 시스템/부팅/페이지파일 디스크, 원본과 같은 디스크, 원본 파티션이 들어가지 않는 용량, 논리 섹터 크기 불일치, 또는 관리자 권한이 없으면 진행할 수 없습니다.

**사용자 확인** — 대상에 기존 파티션이 있으면 **대상 디스크의 모델명을 직접 타이핑**해야 진행됩니다.

**쓰기 직전 재확인** — 작업을 시작하는 순간 디스크를 다시 열거해, 확인한 그 디스크가 지금도 같은 물리 디스크인지 검사합니다(모델·시리얼·용량 대조). USB를 다시 꽂으면 장치 번호가 재배정되기 때문입니다.

시스템 디스크 판별은 WMI가 아니라 커널에 직접 묻고(`IOCTL_VOLUME_GET_VOLUME_DISK_EXTENTS`), 부팅 디스크는 `HKLM\SYSTEM\Setup\SystemPartition` 값으로 판별합니다.

## 어떻게 동작하는가

**실행 중인 시스템 디스크 복제 (VSS).** 부팅되어 쓰고 있는 디스크를 그냥 읽으면 읽는 동안 파일이 계속 바뀌어 결과물이 뒤죽박죽이 됩니다. DiskMigrator는 **VSS 스냅샷**으로 그 시점에 정지된 이미지를 복제합니다. VSS는 *볼륨* 스냅샷이지 *디스크* 스냅샷이 아니므로, 디스크를 조각으로 나눠 각 조각을 알맞은 곳에서 읽습니다 — 파티션 테이블·EFI(FAT32) 파티션은 원시로, NTFS 볼륨은 스냅샷에서.

**대상 오프라인.** 대상에 파티션 테이블을 쓰는 순간 원본과 똑같은 볼륨이 생기고, 온라인 상태이면 Windows가 자동 마운트해 우리가 쓴 데이터 위에 덮어씁니다(실기에서 파일 시스템 영역에만 불일치 617,692건 관측). 그래서 쓰기 전에 대상을 **오프라인**으로 내리고(`DISK_ATTRIBUTE_OFFLINE`), 클론·검증·GPT 보정이 끝난 뒤 다시 온라인으로 올립니다. 볼륨 잠금만으로는 *새로 생기는* 볼륨을 막지 못하므로 부족합니다.

**검증은 대상만 다시 읽습니다.** 복제하면서 각 블록에 실제로 쓴 데이터의 해시(XxHash128)를 기록해 두고, 검증 때 대상만 다시 읽어 그 해시와 비교합니다. 원본(스냅샷)은 다시 읽지 않습니다 — 클라이언트 Windows는 VSS 섀도 저장소를 스냅샷 볼륨 자신에 두어 시간이 지나면 스냅샷 읽기가 드리프트하기 때문입니다. 이 방식은 드리프트에 면역이면서 진짜 쓰기 오류는 정확히 잡습니다. 긴 클론에 대비해 섀도 저장소를 볼륨의 20%(최소 40GB)로 미리 확보합니다.

**GPT 백업 헤더 보정.** GPT는 디스크 끝에 헤더 사본을 둡니다. 대상이 더 크면 이 사본이 디스크 중간에 놓여 문제가 되므로, 복제 후 백업 헤더를 진짜 디스크 끝으로 옮기고 `LastUsableLBA`·CRC32·보호 MBR을 다시 계산합니다.

## 스마트 클론 & 파티션 확장

**스마트 클론 — 빈 영역 건너뛰기.** "스마트 클론" 옵션을 켜면 NTFS 볼륨의 **할당 비트맵**(`FSCTL_GET_VOLUME_BITMAP`)을 읽어 실제로 쓰이는 클러스터만 복사합니다. 1TB 디스크에 실데이터가 200GB뿐이면 200GB만 읽고 쓰므로 크게 빨라집니다. 비트맵은 **스냅샷에서** 읽으므로(라이브는 드리프트) 스냅샷 모드에서만 동작하고, NTFS가 아니거나 비트맵을 못 읽으면 그 파티션은 **통째 복사로 안전하게 되돌립니다** — 스마트 클론은 어디까지나 최적화이고 정확한 복제가 우선입니다. 건너뛴 영역은 대상 파일시스템에서도 "여유 공간"으로 표시되므로 무결성·부팅에 영향이 없습니다.

> 실기 검증: 라이브 C:(931GB 중 392GB 사용) 스냅샷을 스마트 클론하니 42%만 복사, 나머지 539GB를 건너뛰었습니다. 작은 VHD→큰 VHD end-to-end에서 chkdsk 클린 + 테스트 파일 SHA256 전부 일치.

**마지막 파티션 확장.** 작은 디스크를 큰 디스크로 클론하면 뒤쪽에 미할당 공간이 남습니다. "마지막 파티션 확장" 옵션을 켜면 GPT 보정으로 백업 헤더를 끝으로 옮긴 뒤 `diskpart extend`로 마지막 파티션과 NTFS를 **한 번에 정합적으로** 늘립니다(중간에 깨진 상태가 없어 하이브 직접 편집보다 안전).

단, **클론 중 자동 확장은 대체로 실패**합니다 — 클론 중에는 원본이 함께 연결돼 있어 디스크 서명 충돌로 대상 NTFS 볼륨에 접근할 수 없기 때문입니다(best-effort로 시도하고 안 되면 미할당 공간을 남깁니다). **정석은 대상을 단독으로 연결한 뒤**(원본 분리) 마무리하는 것입니다:

- **GUI** — 클론 결과 화면에 남는 공간이 있으면 **"파티션 확장"** 버튼이 나타납니다. 대상을 단독 연결한 상태에서 누르면 확실히 동작합니다.
- **CLI** — `DiskMigrator.VhdTest.exe <디스크번호> --expand-last` (단독 확장 명령).

> 실기 검증: 단독 연결된 대상에서 `--expand-last`로 1GB→1.98GB 확장, 파일 유지, 미할당 0.

**파티션 확대 리사이즈.** "마지막 파티션 확장"은 말 그대로 *마지막* 파티션만 넓힙니다. 하지만 전형적인 Windows 디스크는 `[ESP][MSR][C:][복구]`처럼 C: 뒤에 복구 파티션이 있어, C:를 넓히려면 복구 파티션을 뒤로 밀어야 합니다. 파티션 리사이즈는 **고른 파티션을 확대하고 그 뒤 파티션들을 오른쪽으로 밀어** 이 문제를 해결합니다.

- 각 파티션 데이터는 여전히 1:1 블록 복사(스마트 클론과 호환)이되 **새 오프셋**으로 옮겨집니다. 클론 후 GPT를 새 배치로 다시 쓰는데, **파티션의 고유 GUID·타입·이름을 보존**합니다(BCD가 파티션을 GUID로 참조하므로 보존하지 않으면 부팅이 깨집니다).
- 확대한 파티션의 NTFS는 클론 후 `diskpart extend`로 늘립니다. 클론 중 자동 확장은 원본 동시 연결로 실패하기 쉬우므로(위 "마지막 파티션 확장"과 같은 제약), **대상을 단독 연결한 뒤** GUI "파티션 확장" 버튼 또는 CLI `--expand-part <번호>`로 마무리합니다.
- **확대 전용입니다.** 대상은 원본보다 커야 하며, 축소(대상 < 원본)는 파일시스템 인식 NTFS 축소가 필요해 다음 버전 계획입니다.
- **GPT 원본만 지원합니다.** 리사이즈는 파티션 테이블(GPT)을 새 배치로 다시 쓰는데, MBR 디스크는 이 재작성이 안 되므로 리사이즈 옵션이 막힙니다(MBR은 리사이즈 없이 통째 클론만). GUI는 MBR 원본이면 옵션이 비활성화되고, CLI는 클론 시작 전에 중단합니다.

```powershell
# 파티션 2를 남는 공간 전부로 확대하며 클론
.\DiskMigrator.VhdTest.exe <원본> <대상> --grow 2

# 파티션 2를 특정 크기(GB)로 확대
.\DiskMigrator.VhdTest.exe <원본> <대상> --grow 2 --grow-gb 500

# 리사이즈 마무리: 확대한 파티션의 NTFS를 뒤 미할당 공간까지 채움 (대상 단독 연결)
.\DiskMigrator.VhdTest.exe <대상> --expand-part 2
```

> 실기 검증: `[GROWME 300MB][TAIL 200MB]` 원본을 2GB 대상으로 클론하며 GROWME 확대 → TAIL 자동 시프트, 고유 GUID 보존, GROWME 300MB→1.79GB(볼륨 실사용 증가), 파일 해시 전부 일치, chkdsk 클린.

## 다른 하드웨어에서 부팅하기

시스템 디스크를 클론해 다른 PC에 꽂으면 부팅이 실패할 수 있습니다. DiskMigrator는 이를 예방·검사·복구합니다.

**Universal Restore (하드웨어 독립화).** "새 하드웨어 대비" 옵션을 켜면 클론 후 대상의 SYSTEM 하이브를 손봐 표준 인박스 저장소 드라이버(storahci·stornvme·iaStorAV 등)를 **부팅 시작(Start=0)** 으로 설정해 `0x0000007B (INACCESSIBLE_BOOT_DEVICE)` 를 예방합니다. `reg.exe`에 의존하지 않고 regf 하이브 바이너리를 직접 읽고 씁니다(바꾸는 값은 전부 REG_DWORD라 하이브 구조를 건드리지 않고 4바이트만 덮어씀). 단, 원본에 없는 드라이버는 추가하지 못합니다 — 대상이 Intel VMD/RAID 모드인데 해당 드라이버가 없으면 **대상 BIOS의 저장소 모드를 AHCI로** 바꿔야 합니다.

**부팅 구성 검사.** 실제로 부팅해 보지 않고도 부팅을 막는 흔한 결함을 미리 걸러냅니다. 항목은 심각도로 나뉩니다:

- **치명** — UEFI 부트로더(`bootmgfw.efi`), 유효한 BCD와 winload를 가리키는 OS 로더 항목, **BCD 장치 참조가 이 디스크를 가리키는지**, winload·SYSTEM 하이브 존재.
- **경고** — 폴백 부트로더, 부팅 시작 저장소 드라이버 유무.
- **정보** — 하드웨어 독립성(storahci·stornvme 커버리지).

BCD도 regf 하이브라 Universal Restore와 같은 자체 파서로 읽습니다. **오프라인 클론 대상**(부팅 안 한 디스크)에 써야 잠기지 않은 하이브까지 온전히 검사됩니다. GUI는 클론 성공 후 결과 화면의 **"부팅 구성 검사"** 버튼으로, CLI는 `--boot-check`로 실행합니다(읽기 전용).

**부팅 복구 — 0xc000000e.** 클론을 원본과 같은 켜진 Windows에 연결하면, 같은 GPT 디스크 GUID를 감지한 Windows가 클론의 디스크 GUID를 **재서명**합니다. 그러면 BCD의 `device`/`osdevice`에 내장된 옛 디스크 GUID가 어긋나 부팅이 `0xc000000e`("필요한 장치를 연결할 수 없음")로 실패합니다. 검사가 이를 탐지하면 GUI에 **"부팅 복구"** 버튼이 나타나고, CLI는 `--fix-boot`로 고칩니다 — ESP에 임시 드라이브 문자를 부여하고 `bcdedit`으로 장치 참조를 현재 파티션으로 다시 씁니다(ESP의 BCD만 수정). **예방: 클론을 원본과 동시에 켜진 상태로 두지 마십시오.**

```powershell
# 부팅 구성 검사 (읽기 전용, 관리자 필요)
.\DiskMigrator.VhdTest.exe <디스크번호> --boot-check

# 부팅 복구 (0xc000000e 해결, ESP에만 씀)
.\DiskMigrator.VhdTest.exe <디스크번호> --fix-boot

# 마지막 파티션 확장 (남는 미할당 공간 합치기, 대상 단독 연결 시 권장)
.\DiskMigrator.VhdTest.exe <디스크번호> --expand-last
```

## 빌드 & 실행

```bash
# 요구사항: .NET 8 SDK 이상
dotnet build
dotnet test        # 실제 디스크를 건드리지 않습니다

# 배포용 단일 exe — 런타임이 없는 PC에서도 실행됩니다
dotnet publish src/DiskMigrator.App -c Release -o publish
```

`app.manifest`에 `requireAdministrator`가 걸려 있어 실행 시 UAC 상승을 요구합니다(원시 디스크 접근·볼륨 잠금·VSS 모두 관리자 권한 필요).

**진단 도구** — 실제 하드웨어에서 저수준 계층을 확인합니다. 읽기만 하며 어떤 디스크에도 쓰지 않습니다:

```bash
dotnet run --project tools/DiskMigrator.Probe   # 디스크 열거 + SafetyGuard 판정
```

클론을 시도하기 전에 이 출력으로 **시스템 디스크가 정확히 식별되는지** 반드시 확인하십시오.

## 구조

위험한 저수준 코드와 UI를 격리하고, 실제 디스크 없이 엔진을 테스트할 수 있게 나눴습니다.

```
src/
  DiskMigrator.Core/       플랫폼 독립 — IBlockDevice 추상화, 안전 규칙, 엔진, GPT/BCD
  DiskMigrator.Windows/    Win32 P/Invoke — 원시 디스크·볼륨·VSS·부팅 복구
  DiskMigrator.App/        WPF (MVVM)
tests/
  DiskMigrator.Core.Tests/ 실제 디스크 없이 엔진 전체를 검증
tools/
  DiskMigrator.Probe/      읽기 전용 하드웨어 진단
  DiskMigrator.VhdTest/    VHD 클론 통합 테스트(가상 디스크에만 씀) + 부팅 검사·복구
  vhd-clone-test.ps1       VHD 생성 → 클론 → 검증 → 정리
```

핵심 설계는 `IBlockDevice`입니다. 클론 엔진은 이 인터페이스만 알기 때문에, 파일·메모리 기반 가짜 장치로 불량 섹터·취소·검증 실패까지 전부 테스트할 수 있습니다.

## 검증 현황

**🎉 다른 하드웨어에서 부팅 성공.** Universal Restore로 클론한 시스템 디스크를 **원본과 다른 PC**(ASRock B360M / i7-9700)에 옮겨 **부팅에 성공**했습니다 — 하드웨어 독립 마이그레이션을 실기에서 실증했습니다. 이 과정에서 두 가지를 확인했고 둘 다 도구가 돕습니다: 대상 BIOS의 RAID→AHCI 전환(사용자가 BIOS에서 처리, 검사가 드라이버 상태를 미리 보여 줌)과 `0xc000000e`(검사가 탐지, 부팅 복구가 자동 수정).

**그 밖에 검증된 것** — 원시 디스크 읽기/쓰기 경로, 볼륨 잠금·오프라인, VSS 스냅샷 조각 복제, 복제-중-해시 검증, GPT 백업 헤더 보정, Universal Restore 하이브 편집(실기), 부팅 검사·복구(실기), **스마트 클론**(라이브 C: 스냅샷 실기 + 작은 VHD→큰 VHD end-to-end, chkdsk 클린·SHA256 일치), **마지막 파티션 확장**(단독 대상 실기 1GB→1.98GB), **파티션 확대 리사이즈**(VHD end-to-end: 파티션 확대+뒤 파티션 시프트, GUID 보존, 300MB→1.79GB, 파일 해시 일치·chkdsk 클린). 총 124개 단위 테스트.

**범위 밖** — 대용량 디스크에서의 장시간 동작(실기 클론은 약 216GB), 파일시스템 인식 축소(대상 < 원본)·이미지 백업(미구현). 파티션 리사이즈 GUI는 클릭-스루 미검증(엔진·CLI는 실기 검증).

여전히 **초기 버전**입니다. 되돌릴 수 없는 작업이므로 반드시 중요한 데이터를 먼저 백업하십시오.

## 기여와 테스트

실제 디스크에 쓰는 테스트는 **반드시 버려도 되는 USB/HDD 또는 가상머신**에서 하십시오. 개발 중에는 `FileBlockDevice`·`FaultyBlockDevice`로 충분히 검증할 수 있습니다. 원시 디스크 접근 도구는 백신이 의심할 수 있으며, 코드를 공개하는 이유 중 하나입니다.
